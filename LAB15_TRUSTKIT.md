# ЛР15 — сравнение способов пиннинга (усложнение)

| Критерий | Network Security Config | OkHttp CertificatePinner | TrustKit-Android |
|---|---|---|---|
| Где задаётся | XML, всё приложение | код, один клиент | XML (как NSC) + библиотека |
| API | 24+ | любой | 17+ (бэкпорт NSC) |
| WebView / HttpURLConnection | да | нет | частично |
| Срок действия пинов | `expiration` (после срока пины НЕ проверяются) | нет, проверяет всегда (fail closed) | есть |
| Отчёт о нарушении | нет | исключение в коде | report-uri на сервер |
| Режим «только отчёт» | нет | нет | enforcePinning=false |
| Зависимость | нет | уже есть OkHttp | +1 библиотека, давно не обновлялась |

**Выбор в Фонотеке:** NSC + CertificatePinner одновременно (два независимых уровня). minSdk 24, поэтому бэкпорт TrustKit не нужен, а report-uri при учебном localhost некуда отправлять. После expiration NSC перестаёт проверять пины, но OkHttp продолжает — канал всё равно закрыт для чужого сертификата.

## Ротация pin-set
1. В NSC и в LocalMockTlsClient заранее есть 2 пина: текущий и запасной.
2. Выпускается приложение с обоими пинами → сервер переходит на запасной сертификат → старые клиенты работают.
3. В следующем релизе старый пин убирается, добавляется новый запасной. expiration обновляется заранее.
Проверка: `OwnedBackupPinRotationTest` (primary → ок, backup → ок, третий доверенный, но не запиненный → отказ).
